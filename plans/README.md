## Findings considered and rejected

- **D1 for the product catalog:** rejected for the first version. The current upstream snapshot is roughly 105,000 offer rows before indexes; D1 Free allows 100,000 rows written per day and index maintenance also counts as writes. The workload is a daily bulk rebuild followed by read-heavy search, so immutable R2 artifacts are cheaper and simpler.
- **A public R2 custom domain and Tiered Cache in v1:** deferred. Hosted and self-hosted deployments both use the private R2 binding. Add a second cached read path only when measured latency or Class B cost warrants its code and operational topology.
- **Catalog lifecycle/cleanup in v1:** rejected. Immutable snapshots preserve manifest-last publication safety, and the measured daily artifact adds only about 14 GB in a year. Retaining them avoids an S3/listing dependency, broader operator credentials, and any chance of deleting a live snapshot; cleanup waits for measured need.
- **R2 for shopping lists:** rejected. Catalog data and capability-held state have different ownership and deletion needs. One small list document belongs in its own SQLite-backed Durable Object and never in the catalog bucket.
- **A generic shared storage package now:** rejected. `CONTRIBUTING.md` says source-specific adapters stay inside their owning MCP until two MCPs genuinely share them. Publish a narrow catalog interface and documented artifact format from `mcp-groceries`; extract it only when a second MCP needs it.
- **Sharing the grocery bucket or list namespace with other MCPs:** rejected. Reuse Cloudflare products and patterns, not resources with unrelated ownership, provenance, retention, or credentials. A future MCP should get its own bucket or Durable Object namespace when those boundaries differ.
- **A server-side birthday-party planner or LLM:** rejected. Hermes/OpenClaw should reason from the user's occasion and call `plan_grocery_basket` with concrete items and quantities. Stamppot's job is deterministic product matching, package arithmetic, price comparison, totals, and explicit uncertainty.
- **Price history, price drops, and watches in v1:** deferred. Together they require a temporal artifact model, catalog diffing, retention, direct offer lookup, extra Durable Object state, and a real polling/notification consumer. Current-price search and repricing remain in scope.
- **Caller-generated IDs, a stored quote, or version-pinned replay:** rejected. Ordered input plus returned `lineNumber` correlates results, and complete unpinned `replayInput` supports follow-up calls while intentionally refreshing to current prices.
- **Fine-grained list mutations and revisions:** rejected for v1. A list is capped at 20 lines, so agents get and replace one complete document. Concurrent callers use documented last-write-wins semantics.
- **Treating an MCP connection/chat as shopping-list identity:** rejected. Remote MCP requests are stateless and clients reset or compact conversations differently. Persisted lists use an explicit bearer `listKey`; losing it is unrecoverable in v1.
- **MCP operation annotations in this feature:** deferred. Complete nested schema descriptions are required; changing core solely to add optional hint metadata is not necessary for the grocery jobs.
- **A self-hosting setup wizard:** rejected for v1. The catalog sync CLI and a copy-paste Wrangler runbook cover clone-and-run without maintaining a second program that provisions resources or edits configuration.
